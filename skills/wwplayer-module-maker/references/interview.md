# 模块制作问答

先确定用户想做什么，再补充该类型真正需要的信息。能力菜单面向使用者，不要求先了解入口 type 或宿主实现。

## 启动：先展示可制作的类型

用户只调用 skill，或尚未说清目标时，第一轮展示下面的能力概览，每项保持一句话：

| 可制作的类型 | 用途 |
| --- | --- |
| 榜单 / 片单 / 专题 | 热门、高分、公开片单、系列作品或自定义精选 |
| 分类浏览 | 按类型、年份、地区等分类进入内容列表 |
| 影视搜索 | 给指定来源增加关键词搜索 |
| 完整影视内容源 | 电影或剧集目录、详情、季集和播放 |
| 播放资源 / 多线路 | 为影片或单集匹配播放版本、清晰度和线路 |
| 在线字幕 | 搜索并加载指定语言的字幕 |
| 弹幕来源 | 直接读取弹幕，或搜索作品、选择分集后加载 |
| 综合模块 | 将需要的几项能力组合在一个模块中 |

同时说明也能修改或迁移已有 JS。依照宿主交互规则展示能力清单，再用一句开放式问题了解用户想实现的模块；支持直接描述需求，不要求固定编号或单选。

这一轮只帮助选择类型。用户还没选定时，不运行构建、校验或来源联网，不创建模块文件，不把来源、参数、认证和样本一次性抛给用户。

## 选定后：逐步了解来源与行为

先沿用对话中已知的类型、地址、已有文件和功能，跳过已有答案。每轮优先一个影响实现的问题；两个紧密相关问题可合并，避免问卷式收集。

1. **来源**：需要联网的模块先了解站点 / 服务地址或已有 JS；静态片单则了解条目或整理规则。资料已给出时先读取，不要求重新提交。
2. **关键行为**：按下面的类型指引补充尚缺信息。能由来源、样本或合理默认值确定的细节不再逐项确认。
3. **开始制作**：信息足够实现所选能力就进入相关配方。不要求用户填写全部选项，也不为名称、文件名、默认页数等常规选择反复停下。

| 已选类型 | 来源明确后，按需了解的重点 |
| --- | --- |
| 榜单 / 片单 / 专题 | 使用现成榜单、公开片单还是自定义规则；需要的筛选或排序 |
| 分类浏览 | 希望按哪些维度组织；已有目录怎样进入分类后的列表 |
| 影视搜索 | 搜索哪类内容；结果只展示作品信息，还是进入来源自己的详情 / 播放 |
| 完整影视内容源 | 电影、剧集或两者；来源是否已有季集目录及播放解析 |
| 播放资源 / 多线路 | 如何识别目标影片 / 单集；来源可提供哪些线路或清晰度 |
| 在线字幕 | 字幕服务或文件来源；优先语言；已有接口是否返回独立字幕文件 |
| 弹幕来源 | 弹幕服务地址；已有接口直接返回内容，还是需要作品与分集选择 |
| 综合模块 | 用户最关心的核心能力与需要组合的其他能力；不默认全部实现 |
| 已有模块修改 / 迁移 | 原 JS 或路径；希望保留、增加或改变的行为 |

这些是询问方向，不是每次都问的固定清单。接口样本缺少但可以取得公开文档时先核对来源；拿不到决定性资料时，只询问当前阻碍实现的那一项。

## 认证与其他可选扩展

Cookie、Bearer Token、API Key、自定义请求头、登录流程、可选筛选与用户偏好不是所有模块的前置条件。不要因为某个模板包含 apiToken 就要求用户配置认证。

只有用户主动提及，或来源文档 / 返回内容表明可能需要时，顺带提示一次可选方案。例如：

> 这个来源可能涉及登录，可以预留 Cookie 或 Token 配置，使用时在模块设置填写；也可以先完成公开内容部分。

用户不选择扩展时继续已确认范围，不反复追问。需要配置时先了解认证方式、字段或脱敏样本，无需让用户把真实凭据发到对话里。确认要保留的认证输入默认留空，按实际来源按需使用。

预留的认证参数按可选字段生成，不默认设置 required: true。真正需要认证的调用在所属接口处说明缺少配置，不因此阻断其他无需认证的功能。

如果来源的目标接口确实必须认证，应说明该接口的真实要求；先完成仍可实现的结构或公开路径，将受影响的联网验收标为待本地配置。不能把认证失败改成空成功结果，也不能声称尚未验证的登录路径可用。

## 衔接示例

- 用户仅输入 `$wwplayer-module-maker`：先展示能力概览，再了解想做的模块。
- 用户回复“字幕”：接着了解字幕来源，不立即要求 Cookie、Token、语言、样本一次齐全。
- 用户已经给出字幕服务及“优先中文”：保留这两项，核对服务资料，仅补充当前还缺的关键内容。
- 用户说“没有 Cookie”：没有认证需求证据时继续公开路径；存在真实登录要求时说明受影响的具体能力，保留本地填写配置的方式。
- 用户直接给出完整来源、响应和需求：进入相应配方，不重放菜单或要求再次确认已给出的答案。
- 用户要求修改 skill 的问答方式：修改 skill，不反问要制作哪个来源。

实际字段及制作配方分别见[开发指南](development-guide.md)和[制作配方](recipes.md)。
