# 模块制作问答

模块用途回答“提供哪种内容”，模块能力回答“在这个用途下能做什么”，来源与接入方式回答“数据从哪里来”。先明确用途，再逐步了解相关能力和来源。

## 启动：按提供的内容分组

用户只调用 skill，或尚未说清目标时，第一轮只展示下面三类及简短用途：

| 模块用途 | 可以提供的内容 |
| --- | --- |
| 影视内容模块 | 影视资料、推荐片单或可播放的影视来源 |
| 字幕模块 | 可搜索和加载的字幕来源 |
| 弹幕模块 | 可匹配和加载的弹幕来源 |

依照宿主交互规则展示用途概览，再用一句开放式问题了解用户想实现的模块。支持自然描述和跨用途组合，不要求固定编号或单选；组合不另设一种“综合模块”。已有 JS 的修改与迁移作为任务方式承接，不混入用途分类。

搜索、分类浏览、分页、多线路、清晰度、榜单 / 片单形态都不是与上述三类并列的模块类型。API、HTML、静态数据也不作为启动选项。这些留到用户选定用途后按需了解，开发用的入口 type 不在第一轮展示。

这一轮只帮助明确用途。用户还没选定时，不运行构建、校验或来源联网，不创建模块文件，不把来源、参数、认证和样本一次性抛给用户。

## 选定后：逐步了解能力与来源

沿用对话中已知的用途、能力、地址和已有文件，跳过已有答案。每轮优先一个影响实现的问题；两个紧密相关问题可合并，避免问卷式收集。

| 已明确的用途 | 接下来按需了解 |
| --- | --- |
| 影视内容 | 主要提供影视资料 / 推荐片单，还是可播放来源；服务地址、已有片单或 JS；按目标补充浏览、筛选、搜索、详情、季集及线路需求 |
| 字幕 | 字幕服务或文件来源；优先语言；如何识别影片 / 单集及取得可加载文件 |
| 弹幕 | 弹幕服务地址；如何匹配作品 / 分集及取得弹幕内容 |

先问当前最不明确的一点。例如用户只说“影视内容”，先了解希望提供什么内容；用户已经说“做一个豆瓣公开片单”，就沿用这一用途和片单形态，接着了解所需片单，不再追问是否要播放。

影视内容不要求全套能力。只做独立搜索、只返回播放资源或只展示静态片单都可以，不强加目录、分类、搜索或播放。字幕和弹幕也按真实来源确定是否需要搜索、手动选择或直接读取，不预设完整流程。

来源可用的能力先从用户资料或公开文档核对，技术入口由开发者映射。信息足够实现用户所需范围时就开始制作，不把能力表当作必须全部填写的清单，也不为名称、文件名等常规默认值反复停下。

需要修改或迁移已有模块时，先承接原 JS 和需要改变的行为，再确定相关用途与能力。拿不到决定性协议资料时，只询问当前阻碍实现的那一项。

## 认证与其他可选扩展

Cookie、Bearer Token、API Key、自定义请求头、登录流程、可选筛选与用户偏好不是所有模块的前置条件。不要因为某个模板包含 apiToken 就要求用户配置认证。

只有用户主动提及，或来源文档 / 返回内容表明可能需要时，顺带提示一次可选方案。例如：

> 这个来源可能涉及登录，可以预留 Cookie 或 Token 配置，使用时在模块设置填写；也可以先完成公开内容部分。

用户不选择扩展时继续已确认范围，不反复追问。需要配置时先了解认证方式、字段或脱敏样本，无需让用户把真实凭据发到对话里。确认要保留的认证输入默认留空，按实际来源按需使用。

预留的认证参数按可选字段生成，不默认设置 required: true。真正需要认证的调用在所属接口处说明缺少配置，不因此阻断其他无需认证的功能。

如果来源的目标接口确实必须认证，应说明该接口的真实要求；先完成仍可实现的结构或公开路径，将受影响的联网验收标为待本地配置。不能把认证失败改成空成功结果，也不能声称尚未验证的登录路径可用。

## 衔接示例

- 用户仅输入 `$wwplayer-module-maker`：先展示影视内容、字幕、弹幕三类用途，再了解想做的模块。
- 用户回复“影视内容”：先了解主要想提供哪种影视内容，不一次性询问所有能力。
- 用户说“只做影视搜索”：承接为影视内容模块的搜索能力，接着了解搜索来源，不要求补目录或播放。
- 用户说“想加分类浏览”：承接分类浏览需求，了解对应内容来源，不把“分类模块”当作新的用途类别。
- 用户说“资源和字幕都要”：将影视内容与字幕用途组合，再了解各自来源，不要求另选“综合模块”。
- 用户回复“字幕”：接着了解字幕来源，不立即要求 Cookie、Token、语言、样本一次齐全。
- 用户已经给出字幕服务及“优先中文”：保留这两项，核对服务资料，仅补充当前还缺的关键内容。
- 用户说“没有 Cookie”：没有认证需求证据时继续公开路径；存在真实登录要求时说明受影响的具体能力，保留本地填写配置的方式。
- 用户直接给出完整来源、响应和需求：进入相应配方，不重放菜单或要求再次确认已给出的答案。
- 用户要求修改 skill 的问答方式：修改 skill，不反问要制作哪个来源。

实际字段及制作配方分别见[开发指南](development-guide.md)和[制作配方](recipes.md)。
